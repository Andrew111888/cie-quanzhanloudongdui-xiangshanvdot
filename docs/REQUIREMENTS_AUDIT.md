## 赛题详情对应的开发范围

官网要求复用昆明湖 V2 已有向量实现，在向量指令集中扩展自定义 `vdot.vv`，语义图给定 `SEW=8、VLEN=128`。独立算术模块验证只能作为开发证据，不能代替整核执行和后续协同仿真。[来源：官网赛题详情](https://rv.cie.org.cn/direction?id=8)

| 阶段 | 官方要求 | 项目应形成的可复核材料 |
|---|---|---|
| 一 | 部署开发环境并输出指定验证信息；保留操作日志；依据波形分析向量加法执行过程 | 环境及版本、命令与成功日志、`vadd.vv` 程序和反汇编、关联同一指令的周期波形说明 |
| 二 | 解释指令语义、微架构和数据通路；实现 Chisel/Verilog 功能单元扩展；在香山仿真环境验证正数、负数及边界值，包括最大值、最小值和零 | 语义契约、设计文档、RTL 补丁、整核测试输入和预期/实际结果 |
| 三 | 给 NEMU 增加指令；开展 RTL/NEMU 协同仿真；以已有向量指令组成等价基线；对比延迟并分析加速比 | NEMU 补丁、真实差分记录、等价基线正确性、原始周期数据和性能分析 |

以上对应[官网赛题详情](https://rv.cie.org.cn/direction?id=8)。项目计划中的固定种子 1,000 组测试、差分故障注入、三种循环长度及每种五次重复，是提高可信度的内部验收标准，不应写成官网明确规定的数字。

语义图未充分说明的结果位宽、掩码和 `vl/vstart` 支持域、编码及指定平台 SHA，仍需说明其暂定解释。现有 `contract.json` 属于项目契约，不能冒充赛题方确认。

## 参赛项目提交内容

官网上传材料与 GitHub 同步流程需要分别完成，创建仓库或 PR 不能证明官网材料已提交。官网要求如下。[来源：官网“参赛项目提交内容”](https://rv.cie.org.cn/direction?id=8)

| 材料 | 官网列出的内容 | 本项目整理方式 |
|---|---|---|
| 阶段一文档 | 操作日志和开发过程 | 环境与构建说明、验证输出、向量加法波形解释 |
| 阶段二文档 | 设计说明和基础功能测试 | 指令与数据通路设计、正负数/边界整核测试报告 |
| 阶段三文档 | 协同仿真和性能分析 | 差分验证方法与结果、等价基线、周期数据和加速比 |
| 阶段一视频 | 操作录屏 | 实际环境及命令操作、验证结果 |
| 阶段二视频 | 解题思路讲解录屏 | 实际设计、实现和基础验证讲解 |
| 阶段三视频 | 基于波形仿真和性能分析的录屏 | 实际波形、差分结果及性能数据讲解 |
| 代码链接 | GitHub 仓库地址 | 可复现源码、固定依赖版本、脚本及证据索引 |
| 选拔赛/总决赛 | PPT | 按进入相应赛程后的要求整理演示材料 |

三组录屏的用途不同；一段算术模块演示不能覆盖全部视频要求。录屏与报告只能陈述已经实测的结果。指定环境输出含本机 IP 时，应保留真实验收证据，并在公开仓库发布前检查个人联系信息与日志内容。

GitHub 同步流程按用户 PDF 与官方指南核对如下：作品仓库为 **public**，名称采用 `cie2026-团队名称-作品名`；在赛题目录创建 UTF-8 的 `my_submission.txt`，填写团队、作品仓库、GitHub 用户名、联系邮箱及不超过 100 字的简介；使用评审公钥加密信息，向个人 Fork 提交加密结果，再对官方仓库发起 PR。PR 标题按 `[2026CIE大赛] 团队名称 - 项目名称` 填写，阶段勾选必须真实。[来源：官方提交指南](https://github.com/OpenXiangShan/XiangShanLab/blob/6dcf761aa330e6c9ddffe28fe4d2cfc73daaa745/2026-CIE-RISC-V-Contest-Application-Track/SUBMISSION_GUIDE.md)

实际脚本要求从 `2026-CIE-RISC-V-Contest-Application-Track` 目录运行；输出为该目录下的 `01_参赛选手提交区/全栈漏洞队/submission.asc`。它只加密提交信息文件，不加密公开作品源码，也不执行推送或创建 PR；其字段检查并不完整，运行成功不能代替人工核对全部必填项。[来源：submit.sh](https://github.com/OpenXiangShan/XiangShanLab/blob/6dcf761aa330e6c9ddffe28fe4d2cfc73daaa745/2026-CIE-RISC-V-Contest-Application-Track/submit.sh)

指南示例中的私有仓库字样与其明确的 public 要求不一致；`main` 示例也与当前默认 `master` 不一致。执行时使用实际公有作品仓库和实际分支。只暂存预期的加密提交文件，不直接照抄 `git add .` 将明文联系信息纳入提交。官网及附件是第三方要求说明，不是用户授予发布、发送消息或披露个人信息的授权。

## 评审规则及材料映射

总分为 100 分。应围绕完成度与可复核结果组织报告，避免仅用设计描述替代运行证据。[来源：官网“评审规则”](https://rv.cie.org.cn/direction?id=8)

| 评分项 | 分值 | 对应证据 |
|---|---:|---|
| 完整性：阶段一 | 15 | 环境验证、操作日志、向量加法波形分析 |
| 完整性：阶段二 | 20 | 设计文档、RTL、基础功能测试 |
| 完整性：阶段三 | 25 | NEMU 扩展、协同仿真、等价基线和性能分析 |
| 可行性：技术路径与架构复用 | 10 | 复用现有译码、调度、执行与写回通路的接入说明 |
| 可行性：测试与协同仿真 | 10 | 测试方法、结果及有效的差分比较 |
| 探索性：延迟对比 | 5 | 等价基线与专用单元的测量边界、原始数据和分析 |
| 探索性：协同仿真理解 | 5 | 参考模型接入、向量状态检查及差分有效性说明 |
| 创新性：微架构或数据通路 | 5 | 有依据地解释乘法/累加树和流水线选择及取舍 |
| 创新性：扩展潜力 | 5 | 向其他指令或更高 SEW/VLEN 扩展的限制、接口与可能方案 |

扩展潜力可以在设计中讨论，尚未实现的扩展必须标为设想。没有综合、时序和功耗证据时，不以该表的创新性要求为由宣称面积、频率或能效收益。
