## 分片功能回归

在包含当前测试脚本的实验根目录设置工件路径。使用刚构建的新工程时，令 `ACC_BUILD_ROOT="$PWD"`；使用本机已冻结的整核模型时如下设置。

```sh
source scripts/env.sh
export ACC_BUILD_ROOT="$PWD/build/acc-core-20261106"
export ACC_EMU="$ACC_BUILD_ROOT/third_party/XiangShan/build/emu"
export ACC_REFERENCE_ROOT="$PWD/build/acc-nemu-precedence"
export ACC_REF="$ACC_REFERENCE_ROOT/reference/riscv64-nemu-interpreter-so"
export ACC_NEMU="$ACC_REFERENCE_ROOT/standalone/riscv64-nemu-interpreter"
export ACC_INITIAL_REF="$ACC_BUILD_ROOT/build/nemu/reference/riscv64-nemu-interpreter-so"
export ACC_FLASH="$ACC_BUILD_ROOT/build/workloads/flash.bin"

python3 scripts/run_acc_validation_shards.py \
  --nemu "$ACC_NEMU" --flash "$ACC_FLASH" --shards 16 --jobs 8

python3 scripts/run_acc_validation_shards.py \
  --emu "$ACC_EMU" --reference "$ACC_REF" --flash "$ACC_FLASH" \
  --shards 16 --jobs 8
```

本机修正库位于 `build/acc-nemu-precedence/`。使用刚构建的新工程时，将 `ACC_REFERENCE_ROOT` 改为该工程的 `build/nemu`。复核本轮初始参考的完整原始随机数据时，使用 `ACC_INITIAL_REF`；新运行生成独立回执，不覆盖旧记录。

功能回归固定种子为 `20261106`，将全局编号 `0..1005` 的 6 组定向输入和 1,000 组随机输入分成 16 片，最多同时运行 8 片。每片从未分片随机流中对应的状态开始，合并时检查全局编号恰好覆盖一次、输入计数和独立 Python 校验和。每组输入检查 6 种指令或别名形式和 2 种尾部策略，其中包含原 `vdot` 控制项；原 `vdot` 合计覆盖 2,012 次执行。各片另外重复运行 640 条累加依赖链指令及 7 种非法形式，重复部分不计作新增的独立随机输入。

运行器保存各片源码快照、编译参数、ELF、二进制、原始日志和退出码；全部分片完成后才产生顶层 `results.json`。RTL 轮次必须同时满足 `Difftest enabled.`、真实 `dirty: 0`、完整检查标记、`HIT GOOD TRAP` 和退出码 0。NEMU 独立轮次只验证解释器和软件契约，不能替代整核差分。

`scripts/run_acc_validation.py` 保留未分片入口，默认执行相同的 1,006 组输入。早期未分片整核运行在完成前已停止并由分片运行接替，不能将该早期目录标成通过。复现是否通过只依据本次运行器生成的完整回执。

## 分片性能测量

```sh
python3 scripts/run_acc_benchmark_shards.py \
  --nemu "$ACC_NEMU" --flash "$ACC_FLASH" --shards 8 --jobs 8

python3 scripts/run_acc_benchmark_shards.py \
  --emu "$ACC_EMU" --reference "$ACC_REF" --flash "$ACC_FLASH" \
  --shards 8 --jobs 8
```

性能程序按 36 个独立测量组分成 8 片，最多同时运行 8 片。长点积为 4 条实现路径乘以 `K=32/128/512`，共 12 组；寄存器循环为 2 条实现路径、`1/2/4/8` 条依赖链及 3 种循环长度，共 24 组。每组单独预热并重复 5 次，合并时要求 60 条长点积样本和 120 条寄存器循环样本均完整。分片减少宿主等待时间，测量值仍来自各模拟器内的客体周期计数器。

运行器对每片反汇编进行循环指令和寄存器约束检查，保留每片实际原始日志，再从这些日志合并统计中位数和范围。NEMU 轮次用于结果与程序检查，回执明确标为 `nemu_standalone`，不输出可充当硬件性能证据的 CSV。RTL 轮次才输出硬件性能 CSV。强基线选择与计时边界见[性能方法](累加融合性能方法.md)。

`scripts/run_acc_benchmark.py` 保留逐项日志的完整未分片入口，串口输出更多。本次最终性能采样使用紧凑日志的8片/8并发入口：定向结果输出两个有序摘要，每个测量组一行链低32位列表，程序仍逐次检查全部128位和哨兵，Python独立重建摘要与每条链低位。未完成的旧分片与未分片运行均不混入最终180条样本。单链和多链数字是包含循环、配置和末尾存储的程序片段周期，相邻长度增量也不是裸功能单元延迟。

## 故障参考与恢复

先在应用了累加补丁的构建目录创建错误参考，再回到实验根目录调用当前检查器。

```sh
(
  cd "$ACC_BUILD_ROOT"
  bash scripts/build_fault_reference.sh
) > reports/acc-fault-build.log 2>&1
export ACC_BAD_REF=$(sed -n 's/^FAULT_REFERENCE_BUILT //p' reports/acc-fault-build.log)
python3 scripts/run_acc_fault_check.py --emu "$ACC_EMU" --reference "$ACC_INITIAL_REF" \
  --bad-reference "$ACC_BAD_REF" --flash "$ACC_FLASH"
```

故障库在独立副本中将结果最低位翻转，正常参考库保持不变。专门的小程序使用非零累加器，正常结果为 `0x12345680`，故障库给出 `0x12345681`。检查器要求正确、错误、恢复三轮原始退出码为 `0/1/0`，匹配真实 `v12_low` 差异，并检查新指令有未跳过、未延迟的提交记录；编译失败或普通进程错误不算故障检出。

```sh
python3 scripts/run_acc_precedence.py --emu "$ACC_EMU" \
  --nemu "$ACC_NEMU" --reference "$ACC_REF" --flash "$ACC_FLASH" \
  --old-nemu "$PWD/build/nemu/standalone/riscv64-nemu-interpreter" \
  --old-reference "$ACC_INITIAL_REF"
```

新环境只有修正库时省略两个 `--old-*` 参数。48例覆盖原vdot及累加变体各24种形式：m2/m4/m8的源与目的对齐、mask/v0、vill、fractional LMUL及vstart交叉。旧参考应有20例mtval错误，旧参考整核轮应由真实CSR差分失败；修正轮必须48例全部通过，目的完整128位及vstart保持。成功逐项检查后只输出计数和校验和，失败项另打印实际值；避免UART输出主导短探针的宿主耗时。
