# 实验性vdot.acc指令契约

该实验在原vdot之外增加独立编码，不改变原指令结果。当前候选配置为SEW=8、VLEN=128、LMUL=1、VL=8、vstart=0、vm=1，vta/vma不改变完整结果布局。

```text
partial = sum(int8(vs1[i]) * int8(vs2[i]), i=0..7)
vd[31:0] = (uint32(old_vd[31:0]) + uint32(partial)) mod 2^32
vd[127:32] = 0
```

两源高64位不参与计算，旧目标高96位不参与累加。读取全部源与旧目标后才写回，支持vd=vs1、vd=vs2、两源相同及三者相同。累加的溢出按32位补码回绕，不饱和、不产生溢出异常。

| 字段 | 累加变体 |
|---|---|
| funct6[31:26] | 000001 |
| vm[25] | 1 |
| vs2[24:20] | 源寄存器 |
| vs1[19:15] | 源寄存器 |
| funct3[14:12] | 000 |
| vd[11:7] | 目的寄存器及真实旧累加器 |
| opcode[6:0] | custom-0，0001011 |
| mask / match | 0xfc00707f / 0x0400000b |
| vd12、vs1=v8、vs2=v10 | 0x06a4060b |

原vdot仍匹配0x0000000b，无累加器语义；其第三源继续可设为SrcType.no。累加变体第三源必须保留真实旧目标依赖。

不支持形式产生cause=2、目标与vstart保持原值。执行单元配置检查的xtval为0；非零vstart在译码拒绝，xtval为指令字。NEMU采用与原vdot相同的一次性非架构异常来源标记，随后普通非法指令的mtval仍报告其指令字。

新增程序[acc_validation.c](../examples/acc_validation.c)覆盖非零/负累加器、正负溢出、六种读写别名模式、源高位无关、目标高位清零、1000组随机、单/四独立累加链及七种非法配置。全部别名模式分别使用tu/mu与ta/ma，累加链使用ta/ma，防止错误的尾部依赖消除被测试配置掩盖。NEMU实现使用uint32_t累加，避免C有符号溢出未定义行为。运行器会分别报告NEMU独立运行与RTL/NEMU协同仿真，独立通过不替代整核差分。

此为本工程实验契约，不表述为Zvdota标准兼容实现。
