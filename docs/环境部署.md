# 环境与构建

## 工具版本

已验证环境为x86_64 Linux，使用Java 20、Mill 0.12.3、Scala 2.13.15、Chisel 6.7.0、firtool 1.62.1、Verilator 5.022、RISC-V GCC 13.2.0及宿主GCC 15.2.0。另需Make、Git、Python、Bison、Flex、dtc、zlib/readline/SDL2/zstd开发库和Linux用户systemd会话。

本机工具通过`VDOT_CHIPYARD_ENV`指定，默认目录为`/home/yh/chipyard/.conda-env`。其他机器使用对应版本的安装路径：

```sh
export VDOT_CHIPYARD_ENV=/absolute/path/to/toolchain
export VDOT_VERILATOR_BIN="$VDOT_CHIPYARD_ENV/bin/verilator_bin"
source scripts/env.sh
"$JAVA_HOME/bin/java" -version
"$VDOT_VERILATOR_BIN" --version
riscv64-unknown-elf-gcc --version
```

## 固定上游

在作品仓库的新检出中获取源码。提交清单见[固定来源](../configs/source-manifest.json)。

```sh
pin_repo() {
  local vdot_url=$1 vdot_sha=$2 vdot_dest=$3
  git init "$vdot_dest"
  git -C "$vdot_dest" remote add origin "$vdot_url"
  git -C "$vdot_dest" fetch --depth=1 origin "$vdot_sha"
  git -C "$vdot_dest" checkout --detach "$vdot_sha"
}
mkdir -p third_party
pin_repo https://github.com/OpenXiangShan/XiangShan.git \
  7b16188f7f18a97be69c9b1a2dae8a446eec3b47 third_party/XiangShan
pin_repo https://github.com/OpenXiangShan/NEMU.git \
  d772a9d9e06f663d529bd1c6518480c1ee59ded2 third_party/NEMU
pin_repo https://github.com/OpenXiangShan/xs-env.git \
  822e3581a2757d4a9848b065fd2a3057957b401e third_party/xs-env
git -C third_party/XiangShan submodule update --init
git -C third_party/XiangShan/rocket-chip submodule update --init cde hardfloat
git -C third_party/XiangShan/openLLC submodule update --init openNCB
```

不使用xs-env默认gitlink替换这组昆明湖V2源码。裸机测试使用本项目启动和链接脚本，不依赖AM。

首次构建NEMU前固定其非gitlink资源：


## 应用补丁

```sh
git -C third_party/XiangShan apply --check ../../patches/xiangshan.patch
git -C third_party/XiangShan apply ../../patches/xiangshan.patch
git -C third_party/NEMU apply --check ../../patches/nemu.patch
git -C third_party/NEMU apply ../../patches/nemu.patch
python3 scripts/check_patches.py
```

已应用补丁的目录跳过应用步骤。将改动提交到各自本地Git仓库后再构建，记录实际提交号；模型的dirty标志来自实际源码状态。

## Mill与firtool

```sh
mkdir -p tools/packages tools/firtool-1.62.1/bin
curl --fail --location \
  https://repo.maven.apache.org/maven2/com/lihaoyi/mill-dist/0.12.3/mill-dist-0.12.3.jar \
  -o tools/mill
printf '%s  %s\n' 336346091edc69b248c306ca51aaccb73d888d8bf525ce45e02df89db449b41d tools/mill | sha256sum --check
chmod +x tools/mill
curl --fail --location \
  https://repo.maven.apache.org/maven2/org/chipsalliance/llvm-firtool/1.62.1/llvm-firtool-1.62.1-linux-x64.jar \
  -o tools/packages/firtool.jar
printf '%s  %s\n' 63acdcb58ed12d4c1aa0ecdedc6e2425a252e94eefb75df9253c118d7d222039 tools/packages/firtool.jar | sha256sum --check
unzip -p tools/packages/firtool.jar org.chipsalliance/llvm-firtool/linux-x64/bin/firtool \
  > tools/firtool-1.62.1/bin/firtool
chmod +x tools/firtool-1.62.1/bin/firtool
export VDOT_FIRTOOL="$PWD/tools/firtool-1.62.1/bin/firtool"
```

JVM依赖由固定build.sc从Maven解析。以上下载校验值对应本项目已使用的工件；完整工具环境仍需满足上文的系统依赖。

## 构建

以下是成功整核构建所用的资源设置：

```sh
source scripts/env.sh
export CCACHE_DISABLE=1
export VDOT_MILL_HEAP=512m
export VDOT_JAVA_HEAP=6G
export VDOT_BUILD_MEMORY_MAX=9500M
export VDOT_FIRTOOL_MEMORY_MAX=7000M
export VDOT_COMPILE_MEMORY_MAX=8500M
export VDOT_CPP_JOBS=3
export VDOT_NATIVE_FILE_HEAP=0
export VDOT_HEAP_BACKING_DIR=
export VDOT_USE_JEMALLOC=1
export VDOT_CPP_DECODER_O0=1
export VDOT_INLINE_MULT=1
export VDOT_EMU_TRACE=
bash scripts/build_workloads.sh
bash scripts/build_nemu.sh standalone
bash scripts/build_nemu.sh reference
bash scripts/build_emu.sh
```

无波形模型用于性能测试。采集FST时在独立构建目录设置`VDOT_EMU_TRACE=fst`后构建，并在运行时指定捕获窗口。脚本内的兼容配置处理固定GCC选项、Verilator波形接口和宿主生成内存。

完整构建与运行日志自动写入reports/，镜像及中间文件写入build/。测试命令见[复现说明](复现说明.md)。
