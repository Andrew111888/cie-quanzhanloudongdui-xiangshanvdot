# 累加融合实验录屏要点

本补充实验由参赛者自行录制，原三阶段视频要求仍分别完成。技术文件入口为[架构](累加融合架构.md)、[契约](累加指令契约.md)、[复现命令](累加融合复现.md)及实验结果报告。

## 设计讲解

展示原vdot与新增vdot.acc的区别：原指令累加输入为零，新指令使用旧vd低32位；高96位均清零，溢出按模2^32回绕。说明新增编码、三源读取和TA下保留真实累加依赖。

打开两级数据通路图，解释第一层3:2压缩被提前到乘法级，第二级继续压缩并使用32位前缀加法。两种指令共用8路乘法，流水延迟仍为两级，独立输入接收间隔仍为一拍；这一点与“增加流水级自然增加吞吐”的说法不同。

## 功能与错误检出

按复现入口运行run_acc_validation.py，展示非零初值、正负溢出、TA/TU及别名检查的实际结果。另展示run_acc_pipeline.py及run_acc_registers.py的通过日志。可以使用已完成日志讲解，现场重跑时说明命令及其新证据目录。

run_acc_fault_check.py依次运行正常、错误、恢复三轮。实际探针期望0x12345680，错误参考给出0x12345681，检查Difftest的v12_low差异以及0、1、0退出码。错误轮失败是预期反例；恢复必须通过。

## 性能与资源

展示长点积四条实现、相同K和完整结果，以及1/2/4/8条链的原始CSV。说明预热、五次重复、配置与访存边界，采用两种RVV候选中较快者；寄存器循环增量周期不能称为裸FU延迟。

资源表先比较同轮结构，再展示整核实际生成模块的独立复核。指出1.5 ns正建立裕量、1 ns仍未通过，以及面积仅为相同包装器和零互连条件下的算术模块数据。原型综合不能当作全核功耗或频率结果。
