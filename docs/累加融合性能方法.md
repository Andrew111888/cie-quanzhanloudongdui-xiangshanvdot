# 累加融合实验的性能测量方法

实验保留原vdot的固定8项、不累加语义，新增独立编码的vdot.acc候选。本文规定测量与验收方法，不将交叉编译或静态指令数写成硬件性能结果。

## 指令与结果契约

vdot.acc使用custom-0、funct6=000001、funct3=000，译码mask为0xfc00707f、match为0x0400000b；vm=1。其余源和目标字段与原vdot一致。支持SEW=8、VLEN=128、LMUL=1、VL=8、vstart=0。

```text
dot = sum(signed_int8(vs1[i]) * signed_int8(vs2[i]), i=0..7)
new_vd.low32 = (uint32(old_vd.low32) + dot) modulo 2^32
new_vd.high96 = 0
```

旧vd是实际累加输入，不能按ta/ma目标覆盖规则消除这项真实依赖。原vdot仍不读取旧vd。测试期望值使用uint32运算处理模2^32，避免C有符号溢出。

## 完整长点积：四条实现共同对照

[实验程序](../examples/acc_benchmark.c)计算两连续int8数组沿K维的完整点积，K为32、128、512。

| 编号 | 实现 | 每32项的循环指令数 |
|---|---|---:|
| 0 | 原vdot，四组8项部分和，再由四条e32向量加法累加 | 28 |
| 1 | RVV8有符号扩宽乘法、扩宽归约累加 | 28 |
| 2 | RVV16扩宽乘法、int32通道累加，末尾统一归约 | 16 |
| 3 | vdot.acc，四个独立8项累加器 | 22 |

四条路径均从相同数组加载全部K项，最后只存一次16字节完整结果，低32位是点积、高96位为零。三条旧路径保留原长点积程序的实现；较强RVV16候选采用全部16个活跃元素并跨块保留通道累加器。

每次调用先在计时外将输出填为非零哨兵。cycle/fence起点之后包括向量累加器初始化、必要配置、全部输入加载、循环、跨块累加、末尾归并或归约、完整结果存储与结束fence。标量黄金计算与完整结果检查在计时外。每组先预热一次，再测5次；四路径、三长度共60条正式样本。

基线选择先对两种RVV候选分别计算5次重复的中位周期，再取较小中位数。报告同时给出两种候选及其范围，不因某条较慢而选它作为分子。旧vdot/新acc的比较另列，不以旧vdot取代较强RVV基线。

## 寄存器循环：真实累加链与独立链数量

另预加载同一对8项源向量和8组128位累加器种子，在每条路径中选择1、2、4、8个独立累加链，循环轮数为32、128、512。每轮每个链执行一次点积累加，实际点积次数为“轮数×链数”。

| 链数 | 原vdot+显式vadd，每轮指令 | vdot.acc，每轮指令 |
|---:|---:|---:|
| 1 | 6 | 3 |
| 2 | 8 | 4 |
| 4 | 12 | 6 |
| 8 | 20 | 10 |

原路径先发出本轮各链的vdot，再切换e32，将部分和加入相应累加器，最后恢复e8；acc直接读写相应累加器。所有链的源相同，但目的寄存器分别为v16至v23，不同链之间没有结果依赖。单链每轮则真实依赖上轮累加结果。两条路径最终写回完全相同的128位结果。

种子和源加载在起点前，且每次调用都重新加载相同种子。计时范围包含循环、路径所需的循环内配置、分支，以及每个活跃链的一次完整16字节结果存储；末尾fence纳入范围。每组预热一次后测5次，两路径、四链数、三轮数共120条正式样本。

这是完整寄存器循环片段的延迟/吞吐对照，包含循环和最终存储成本。中位周期除以总点积数得到片段周期/点积，不能称为裸功能单元输入到输出延迟。算术级数及II仍需独立RTL/FST证据。

## 正确性与编译约束

长点积的六类正数、负数、最小值乘最小值、最小值乘最大值、最大值及零，在K=32和512上执行四路径，共48次定向内核。寄存器循环另用六类输入、两路径及四链数执行48次定向检查，正负种子刻意靠近int32边界，检查模2^32溢出。每次运行都检查结果的全部四个32位字；未使用的输出槽必须保持哨兵。

正式样本使用种子20261106的xorshift32输入，C黄金模型独立计算结果。运行器再以Python重建同一输入，核对全部长点积结果、90份完整寄存器链结果及定向校验值。

多指令内联汇编对循环修改的指针、计数使用+&r提前写约束，防止与末尾才读取的输出地址共用GPR。反汇编审计解码32位及压缩指令的GPR写目的，确认输出地址不被循环改写、回跳目标正确、循环指令数及自定义编码数量正确。全部最终向量存储须在循环之后且在两个cycle读数之间。

## 运行与证据

仅编译和审计：

```bash
source scripts/env.sh
python3 scripts/run_acc_benchmark.py --build-only
```

使用新增指令已接通的整核模拟器及对应NEMU参考库：

```bash
python3 scripts/run_acc_benchmark.py \
  --emu /path/to/new/emu \
  --reference /path/to/new/riscv64-nemu-interpreter-so \
  --build-receipt /path/to/build-receipt.json
```

未给--flash时，从固定workloads/flash.S编译；也可显式指定--flash复用固定二进制。工具默认从PATH寻找riscv64-unknown-elf-*，可用--tool-prefix指定完整前缀。默认要求模型报告dirty: 0；开发期若使用--allow-dirty-core，回执保留实际dirty值及该选项，不把它改写为干净构建。

运行器不启用波形，使用真实--diff和--no-squash，要求Difftest enabled、GOOD TRAP及原始退出0。输出reports/acc-benchmark-*保存输入副本、工具版本和摘要、二进制、反汇编、循环审计、命令及原始日志。真实运行成功后才写status=passed的results.json及逐次/汇总CSV；--build-only仅产生built_and_audited_not_simulated的准备记录。

正式结果应同时公开RVV/acc和旧vdot/acc两种比例、每组中位数与范围、全部链数，并结合共同约束下的算术面积及STA评估。指令数减少不保证周期减少，周期减少也不能在缺少时序证据时直接换算为频率或功耗收益。
