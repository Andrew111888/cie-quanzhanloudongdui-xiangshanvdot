# 边界RTL故障变异验证

本实验直接仿真整核构建导出的VdotDatapath.sv，并在三个独立副本中注入位宽、符号扩展和目标高位错误。软件黄金模型逐字节解释两个源的低8项，以有符号整数循环计算点积，逐次比较完整128位结果。原有RTL、香山补丁及NEMU参考实现保持原样。

## 正常与恢复验证

正常模型和恢复模型分别重新生成、编译并运行，各检查以下6项定向输入：

| 输入a/b（前8项） | 期望有符号结果 | 期望完整目标 |
|---|---:|---|
| 1 / 1 | 8 | 00000000000000000000000000000008 |
| -1 / 1 | -8 | 000000000000000000000000fffffff8 |
| -128 / -128 | 131072 | 00000000000000000000000000020000 |
| -128 / 127 | -130048 | 000000000000000000000000fffe0400 |
| 127 / 127 | 129032 | 0000000000000000000000000001f808 |
| 0 / -128 | 0 | 00000000000000000000000000000000 |

两次正例还各检查1000组种子20261106的随机输入，全部1006组算术输入连续进入流水并逐项检查。随后以同一组输入进行1006拍独立enable1/enable2压力，记分板检查乘积级保持、结果级保持及排空。每次正例共检查2013拍完整结果，均以VDOT_RTL_PASS结束并退出0。源高64位填入独立哨兵或随机值。

## 三类真实RTL变异

| 变异 | 检测用例 | 正确值 | 变异后的实际值 | 原始退出码 |
|---|---|---|---|---:|
| 总和错误截为18位后符号扩展 | -128 / -128 | 131072，低32位00020000 | -131072，低32位fffe0000 | 42 |
| 将19位负数错误零扩展至32位 | -1 / 1 | -8，低32位fffffff8 | 524280，低32位0007fff8 | 42 |
| 目标高96位的最低位置1 | 1 / 1 | 00000000000000000000000000000008 | 00000000000000000000000100000008 | 42 |

三个变异模型均成功生成并完成C++编译。失败由RTL_MISMATCH结果断言触发，日志同时给出用例、流水阶段、周期、期望值与实际完整128位值；运行器要求退出码为42、匹配对应的错误数值，且不得出现正例完成标记。编译错误、超时和普通进程失败不计为变异检测成功。

131072超过18位有符号数最大值131071，因此第一个用例直接检验正边界所需的19位总和。负数零扩展用例检查sum[18]到低32位的符号扩展；第三项检查低32位以外的全部目标布局。随后恢复模型从原始RTL的逐字节副本重新构建，重新通过同样的定向、随机及使能压力。

## 证据与复现

输入RTL的SHA256为868ca4b2f21e499a37c14161c72e0776817086eb73a27354102722008de20b89，与生成RTL来源清单及已验收模型一致。原始输入快照、三个变异差分、五次模型生成/构建/运行命令、工具版本、原始退出码及日志摘要见[配套数据](data/boundary-mutations/README.md)。

```bash
python3 scripts/run_boundary_mutations.py \
  --verilator /home/yh/chipyard/.conda-env/bin/verilator \
  --jobs 2
```

五个模型的生成、构建与运行合计16.18秒，单子进程最大RSS为299260KiB；整个服务限制为2GiB内存、禁用交换，并行编译为2路。首次构建遇到宿主对象与Conda链接器混用，已显式固定宿主g++、链接器和归档器后完整重跑，原失败记录单独保留。

本实验覆盖生成数据通路的算术、位宽、完整结果和独立流水使能；指令译码、调度、异常、冲刷及NEMU整核协同验证沿用已有整核验收记录。
